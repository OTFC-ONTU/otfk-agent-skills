# Заливка матеріалів у Google Classroom через API

Папка з інструментами. Працює з робочого акаунта Google Workspace коледжу.

## 1. Разове налаштування Google Cloud (≈15 хв)

1. Відкрий https://console.cloud.google.com/ під **робочим акаунтом коледжу**
   (не під особистим Gmail — інакше API не побачить курси).
2. Вгорі зліва створи новий проєкт, назва будь-яка, напр. `ОТФК Classroom`.
3. **APIs & Services → Library** → знайди **Google Classroom API** → `Enable`.
   Так само увімкни **Google Drive API** – без нього файли лекцій не прикріпити
   (помилка `accessNotConfigured` при `--apply`). Для входу в Cloud Console на
   робочому акаунті має бути ввімкнена двоетапна перевірка (2SV).
4. **APIs & Services → OAuth consent screen**:
   - User type: **Internal** (доступно, бо акаунт у Workspace) → `Create`.
     Internal означає, що перевірка застосунку від Google не потрібна.
   - App name: `ОТФК Classroom Sync`, e-mail підтримки — твій.
   - Scopes можна не додавати вручну, вони запитуються самим скриптом.
5. **APIs & Services → Credentials** → `Create credentials` → **OAuth client ID**
   → Application type: **Desktop app** → `Create` → `Download JSON`.
6. Перейменуй завантажений файл на `credentials.json` і поклади в цю папку.

Якщо на кроці 4 варіанта **Internal** немає або на кроці 6 при вході з'явиться
«Access blocked: this app is blocked» — адміністратор Workspace обмежив сторонні
застосунки. Тоді адміну треба в Admin Console дозволити цей OAuth client ID
(Security → Access and data control → API controls → Manage third-party app access).

## 2. Встановлення бібліотек (разово)

У PowerShell, у цій папці:

    pip install -r requirements.txt

## 3. Перша авторизація

    python classroom_auth.py

Відкриється браузер, вибери робочий акаунт, дай доступ. З'явиться `token.json` —
далі авторизація більше не потрібна.

## 4. Подивитися свої курси

    python classroom_ls.py

Виведе список курсів з їхніми `id`. Потім можна подивитися конкретний курс:

    python classroom_ls.py 123456789012

## 3а. Авторизація без локального браузера (VM, сервер, агент Claude/Codex)

Якщо скрипт запускається там, де браузер не відкриється (наприклад, у VM Cowork):

    python classroom_auth_manual.py url

Відкрий надруковане посилання в будь-якому браузері, увійди **під робочим акаунтом
коледжу** (особистий Gmail дасть «Помилка 403: org_internal»), дозволь доступ.
Браузер перейде на `http://localhost:8765/?code=...` і покаже «сторінка недоступна» –
це нормально. Скопіюй усю адресу з рядка браузера і виконай:

    python classroom_auth_manual.py code "http://localhost:8765/?state=...&code=..."

`token.json` лежить у цій папці (у git він не потрапляє – див. `.gitignore`); якщо папка
синхронізується (OneDrive тощо), після авторизації на одному комп'ютері він працює на всіх. Якщо набір дозволів (SCOPES у `classroom_auth.py`) змінився,
скрипти самі скажуть, що потрібна повторна авторизація.

## 5. Заливка плану

План — це JSON у папці `plans/`. Спочатку завжди холостий прогін:

    python classroom_sync.py plans\<мій-курс>.json

Він нічого не змінює, лише показує, що буде створено. Якщо все влаштовує:

    python classroom_sync.py plans\<мій-курс>.json --apply

Скрипт ідемпотентний: тему або завдання з таким самим заголовком повторно
не створює, нічого не видаляє і не перезаписує. Можна безпечно запускати ще раз
після того, як у план додали нові пункти.

## Формат плану

    {
      "course": { "id": null, "name_hint": "УІТП" },
      "timezone": "Europe/Kiev",
      "topics": [
        {
          "name": "Розділ 1. Назва розділу з РП",
          "items": [
            {
              "type": "material",            // material | assignment | question
              "title": "Лекція 1. Назва теми",
              "description": "Короткий опис.",
              "state": "DRAFT",              // DRAFT або PUBLISHED
              "materials": [ { "link": "https://..." } ]
            },
            {
              "type": "assignment",
              "title": "Практична робота 1. Назва",
              "description": "Що зробити.",
              "maxPoints": 12,
              "dueDate": "2026-10-02",
              "dueTime": "23:59",
              "state": "DRAFT"
            }
          ]
        }
      ]
    }

### Файли (лекції, презентації, силабус)

Замість посилання можна вказати файл із робочої папки (шлях відносно її кореня – батьківської папки `_classroom/` або `OTFK_ROOT`):

    "materials": [
      { "file": "УІПТ КГ/Лекції 2026/Лекція 1.docx" },
      { "file": "УІПТ КГ/Презентації 2026/Лекція 1.pptx" }
    ]

При `--apply` файл завантажується у Drive-папку курсу (та сама, що Classroom
створює для курсу) і прикріплюється як Drive-файл у режимі «перегляд».
Відповідність «шлях → id у Drive» зберігається в `plans/_drive_files.json`:
повторний запуск файл не дублює, а якщо файл змінився локально – оновлює той самий
Drive-файл, і прикріплення в Classroom оновлюється саме.

Файл у OneDrive має бути завантажений локально (не cloud-only, розмір > 0),
інакше скрипт зупиниться з повідомленням.

Прапорець `--only-files` створює лише ті елементи, до яких прикріплено файли
(і їхні теми). Зручно, коли план на весь семестр, а готові поки перші лекції:

    python classroom_sync.py plans\<мій-курс>.json --only-files
    python classroom_sync.py plans\<мій-курс>.json --only-files --apply

## Правила наповнення курсів

Повні правила (структура, бали 12/5, дедлайни, назви, статуси) – у корені:
`skills/google-classroom-otfk/SKILL.md`. Нижче – коротко.

- У кожному курсі Classroom має бути силабус (окрема тема «Силабус та робоча
  програма», перший елемент) і всі матеріали дисципліни.
- У Classroom заливаються лише матеріали поточного навчального року (папки
  «Лекції 2026», «Презентації 2026», силабус 2026). Старі версії не завантажувати.
- Лекції, які вже прочитані, ставити `PUBLISHED`; те, що ще не готове, – `DRAFT`.
- Бали: `course_year` у плані → 12 б. (1–2 курс) або 5 б. (3–4 курс) для всіх активностей.
- Дедлайн = неділя 23:59 тижня `week + 1` (тиждень на виконання), здача після терміну дозволена;
  СР – без дедлайну.
- Теми й елементи створюються у зворотному порядку (Classroom показує нові зверху).
- `--check` перевіряє план за правилами; `--update --apply` дотягує вже створене до плану;
  `classroom_clear.py <courseId>` – очистити курс для перестворення (лише без зданих робіт).

Час здачі пишеться у локальному київському часі — скрипт сам переводить його в UTC,
бо Classroom API зберігає дедлайни лише в UTC.

## Безпека

`credentials.json` і `token.json` — це ключі доступу до твого акаунта.
Вони належать лише твоєму акаунту: не передавай їх нікому, не клади в архіви, чужі папки
і **ніколи не коміть у git** (`.gitignore` цієї папки їх виключає – не змінюй його).

## Приклади планів

Готові плани реальних курсів лежать у `plans/examples/` – беріть за зразок і копіюйте в `plans/` під своїм іменем, замінивши `course.id`, викладача, назви і файли.

`plans/examples/uitp-kg-2026.json` — повний план дисципліни УІТП (КГ) за робочою
програмою 2026: 5 змістовних модулів + окрема тема «Самостійна робота»,
разом 36 елементів (17 лекцій як матеріали, 10 практичних, 5 семінарів/КР,
4 самостійні роботи). Назви й описи взяті з розділів 2.1–2.5 РП.

Стан на 18.09.2026: `course.id` = 884789543028 («3КГ-11 Основи управління
ІТ-проєктами»), `semester_start` = 2026-09-01, прикріплено силабус 2026 і
лекції 1–6 (docx + pptx). Наступні лекції додавати в план у вигляді `"file"` і
запускати sync ще раз.

Поля, які треба заповнити для нового курсу:

- `semester_start` — понеділок першого навчального тижня, напр. `"2026-09-01"`.
  Поки там `null`, дедлайни не ставляться взагалі; щойно дату вписано, скрипт
  рахує їх за номерами тижнів з календарного плану 2.5 (за замовчуванням
  неділя того тижня, 23:59 за Києвом).
- `course.id` — id курсу з `python classroom_ls.py`. Якщо залишити `null`,
  скрипт спробує знайти курс за `name_hint` = «УІТП».

`plans/tik-kb-2026.json` — план дисципліни ТІК (група 4КБ-04, IV курс → 5 б.),
курс 878062469198 «КБ-04 Теорія інформації та кодування»: 5 змістовних модулів +
«Самостійна робота», 38 елементів (17 лекцій, 8 практичних, 5 семінарів/КР, 7 СР, силабус).
Практичні 1–2 прив'язані через `"id"` до завдань, створених вручну у веб-інтерфейсі.

## Обмеження Classroom API (важливо)

- Завдання/матеріали, створені **вручну у веб-інтерфейсі**, API цього проєкту змінювати
  не може (`403 ProjectPermissionDenied`). Скрипт пише `!! НЕ ОНОВЛЕНО` і йде далі;
  назву, опис, дедлайн і тему такого елемента треба поправити руками в Classroom.
- `courseWork.list` без фільтра станів повертає лише PUBLISHED. Скрипти тепер запитують
  `PUBLISHED, DRAFT` явно — інакше чернетки були невидимі й `--apply` створював дублікати.

Усі елементи створюються у стані `DRAFT` — студенти їх не бачать, доки ти сам
не опублікуєш. `maxPoints: 0` означає «без балів», бо РП використовує
національну шкалу; якщо потрібні бали, впиши число.


## Папка як матеріал
`"materials": [{"folder": "ООП РП/Курсові/Завдання 3РП-11", "pattern": "*.pdf", "name": "Індивідуальні завдання на КР 3РП-11"}]` – `drive_files.ensure_folder` створює Drive-папку в папці курсу (кеш `folder:<шлях>`), вантажить/оновлює файли в ній і прикріплює папку одним матеріалом. Нові файли в локальній папці догружаються при наступному `--apply`, але до вже створеного матеріалу нічого перепідключати не треба – папка та сама.
